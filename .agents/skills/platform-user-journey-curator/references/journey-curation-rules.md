# Journey Curation Rules

## Rule 1: Journey First

Do not derive implementation work until the journey is described.

## Rule 2: One Journey, One User Goal

A journey should have one primary persona and one main user goal.

## Rule 3: Evidence Must Be Visible

Every journey should state evidence sources and confidence level.

## Rule 4: Technical Detail Is an Addendum

Technical details support the journey; they are not the journey.

## Rule 5: Derive, Do Not Invent

Every artifact should trace to a journey stage, pain point, opportunity, or success metric.

## Rule 6: Keep Feature Slices Small

Prefer small, coherent slices with visible user value.

## Rule 7: Escalate Architecture Changes

If the derived work changes platform architecture, module boundaries, persistence, identity, tenant model, or core workflow strategy, recommend an ADR.
