# Roadmap Curation Rules

1. Roadmaps explain why and sequence what comes next.
2. Tickets come after approval, unless explicitly provisional.
3. MVP is the smallest coherent useful version, not every desired feature.
4. Long-term goals must shape short-term decisions without bloating MVP.
5. Every ticket should trace back to a roadmap section and, when applicable, a journey stage.
6. Architecture changes should become ADRs, not hidden ticket assumptions.
7. Use phases when dates are unknown.
8. Keep one source of truth: roadmap for direction, task file or tracker for execution.
