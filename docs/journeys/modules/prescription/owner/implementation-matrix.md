# Prescription Module Journey Implementation Matrix

This matrix is the source of truth for Prescription Module owner-journey implementation status as aligned to the current Prescription module implementation.
Status enum values: `implemented`, `partial`, `missing`.

## Current Implemented Surfaces

| Surface | Current implementation |
| --- | --- |
| Owner routes | `AppRoutes.Prescriptions.OwnerPrescriptions`, `OwnerPrescriptionCreate`, `OwnerPrescriptionCreateTemplate`, `OwnerPrescriptionTemplate`, `OwnerPrescriptionOperationalDashboard`, `OwnerPrescriptionReferenceDataAdmin`, `OwnerPrescriptionCredentialSetup`. |
| Support routes | `AppRoutes.Prescriptions.SupportPrescriptionReconciliationDesk`. |
| Owner/admin pages | `OwnerPrescriptionsPage`, `OwnerPrescriptionCreatePage`, `OwnerPrescriptionDetailPage`, `OwnerPrescriptionOperationalDashboardPage`, `OwnerPrescriptionReferenceDataAdminPage`, `OwnerPrescriptionCredentialSetupPage`. |
| Owner/admin components | `PrescriptionsList`, `PrescriptionDetail`, `PayerSelectorPanel`, `EligibilityPanel`, `PrescriptionItemsGrid`, `AddPrescriptionItemDialog`, `PrescriptionSubmitPanel`, `PrescriptionTimeline`, `PaperFallbackPanel`, `PaperFallbackDialog`, `PrescriptionStatusBadge`, `PrescriptionPrintView`, `CancelReasonDialog`, `CredentialSetupGrid`, `CredentialConfigureDialog`, `ReferenceDataAdminDashboard`, `PaperFallbackCertificate`. |
| Support/operations components | `ReconciliationDesk`, `PrescriptionOperationalDashboard`. |
| Command/query boundary | Commands mutate prescription state (`CreateDraftCommand`, `AddItemCommand`, `RemoveItemCommand`, `SetProviderCommand`, `ValidateDraftCommand`, `SubmitPrescriptionCommand`, `EditPrescriptionCommand`, `CancelPrescriptionCommand`, `RecordEligibilityCommand`, `SaveCredentialCommand`, `TestCredentialCommand`, `RevokeCredentialCommand`, `EscalateCommand`, recovery/reference-sync commands). Queries read state (`GetPrescriptionQuery`, `GetPrescriptionHistoryQuery`, `GetEligibilityQuery`, `GetAvailableProvidersQuery`, `GetCredentialSetupGridQuery`, reconciliation/observability queries). |
| Integration boundary | Core application depends on `IInsuranceProviderAdapter` and `IInsuranceProviderRegistry`; provider-specific adapters exist for Tamin, Ditas, and Salamat, with resilience decoration and error mapping in infrastructure. |
| Reference-code boundary | Prescription fetches provider reference data through adapters but delegates provider code persistence/search ownership to the Medical module. |
| Single lifecycle source of truth | `PrescriptionStatus` is the canonical platform status; provider-native statuses are mapped into it by adapters/handlers. |
