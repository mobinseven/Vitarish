# Prescription Module Journey Implementation Matrix

This matrix is the source of truth for Prescription Module journey implementation status as aligned to the current Prescription module implementation.
Status enum values: `implemented`, `partial`, `missing`.

## Current Implemented Surfaces

| Surface | Current implementation |
| --- | --- |
| Owner routes | `AppRoutes.Prescriptions.OwnerPrescriptions`, `OwnerPrescriptionCreate`, `OwnerPrescriptionCreateTemplate`, `OwnerPrescriptionTemplate`, `OwnerPrescriptionOperationalDashboard`, `OwnerPrescriptionReferenceDataAdmin`, `OwnerPrescriptionCredentialSetup`. |
| Doctor-facing pages | `OwnerPrescriptionsPage`, `OwnerPrescriptionCreatePage`, `OwnerPrescriptionDetailPage`, `OwnerPrescriptionOperationalDashboardPage`, `OwnerPrescriptionReferenceDataAdminPage`, `OwnerPrescriptionCredentialSetupPage`. |
| Doctor-facing components | `PrescriptionsList`, `PrescriptionDetail`, `PayerSelectorPanel`, `EligibilityPanel`, `PrescriptionItemsGrid`, `AddPrescriptionItemDialog`, `PrescriptionSubmitPanel`, `PrescriptionTimeline`, `PaperFallbackPanel`, `PaperFallbackDialog`, `PrescriptionStatusBadge`, `PrescriptionPrintView`, `CancelReasonDialog`, `CredentialSetupGrid`, `CredentialConfigureDialog`, `PaperFallbackCertificate`. |
| Support/admin components available in module | `ReconciliationDesk`, `PrescriptionOperationalDashboard`, `ReferenceDataAdminDashboard`, `ProviderManagementGrid`, `ProviderRegistrationDialog`. All now have routed host pages with role-based access policies. |
| Command/query boundary | Commands mutate prescription state (`CreateDraftCommand`, `AddItemCommand`, `RemoveItemCommand`, `SetProviderCommand`, `ValidateDraftCommand`, `SubmitPrescriptionCommand`, `EditPrescriptionCommand`, `CancelPrescriptionCommand`, `RecordEligibilityCommand`, `SaveCredentialCommand`, `TestCredentialCommand`, `RevokeCredentialCommand`, `RegisterProviderCommand`, `UpdateProviderCommand`, `SetProviderCapabilitiesCommand`, `SetProviderStatusCommand`, `TestProviderConnectivityCommand`, `EscalateCommand`, recovery/reference commands). Queries read state (`GetPrescriptionQuery`, `GetPrescriptionHistoryQuery`, `GetEligibilityQuery`, `GetPatientCoveragesQuery`, `GetCredentialSetupGridQuery`, `GetProviderManagementGridQuery`, reference/reconciliation/observability queries). |
| Integration boundary | Core application depends on `IInsuranceProviderAdapter` and `IInsuranceProviderRegistry`; provider-specific adapters exist for Tamin, Ditas, and Salamat, with resilience decoration and error mapping in infrastructure. |
| Single lifecycle source of truth | `PrescriptionStatus` is the canonical platform status; provider-native statuses are mapped into it by adapters/handlers. |
