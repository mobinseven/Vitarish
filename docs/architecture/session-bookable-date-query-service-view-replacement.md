# SessionBookableDateQueryService view-backed replacement strategy

## Status

Proposed replacement path for `SessionBookableDateQueryService` read paths.

## Problem

`SessionBookableDateQueryService` currently builds bookable dates by combining database reads with service-side recurrence expansion, booking-window checks, closed-date filtering, and reservation aggregation. That keeps slot availability correct, but it also means the read path must load session entities and re-run projection logic in memory for every date range request.

The existing `vw_SessionReservation` view can only aggregate dates that already have reservation rows. It cannot represent future bookable slots with zero reservations, so it is not a complete replacement for service-side slot projection.

## Decision

Move bookable-slot projection to database-backed read models in small steps:

1. Normalize policy data that the database must query.
2. Materialize session occurrences so future slots exist without reservation rows.
3. Add a dedicated bookable-slot SQL view over occurrences, sessions, reservation aggregates, and closed dates.
4. Expose the view through a specific EF read model and repository contract.
5. Route bookable date/slot queries through that repository, leaving commands and booking validation unchanged.

This keeps the service simple: it validates query input, delegates read projection, and maps results for callers.

## Target data shape

### `SessionClosedDates`

Replace JSON-backed closed-date filtering for read projection with a relational source:

| Column | Purpose |
| --- | --- |
| `TenantId` | Tenant partition key. |
| `SessionId` | Session that owns the closed date. |
| `Date` | Local session date that is not bookable. |
| `Reason` | Optional operator-facing reason. |

Recommended key and indexes:

- Primary key: `(TenantId, SessionId, Date)`.
- Foreign key: `SessionId` to `Sessions.Id` with cascade delete.
- Index: `(TenantId, Date)` only if cross-session closure queries need it.

The JSON `BookingPolicy.ClosedDates` can be retained temporarily as write-model compatibility during migration, but `SessionClosedDates` becomes the source for read projection.

### `SessionOccurrences`

Materialize recurrence into one row per session/date:

| Column | Purpose |
| --- | --- |
| `TenantId` | Tenant partition key. |
| `SessionId` | Session that owns the occurrence. |
| `Date` | Local session date. |
| `StartTimeUtc` | Occurrence start timestamp used by booking-window predicates and ordering. |
| `EndTimeUtc` | Occurrence end timestamp. |
| `Status` | Optional occurrence status if individual occurrences need cancellation/override later. |

Recommended key and indexes:

- Primary key: `(TenantId, SessionId, Date)`.
- Index: `(TenantId, Date, SessionId)` for calendar range reads.
- Index: `(TenantId, SessionId, StartTimeUtc)` for per-session future reads.

Occurrences should be generated by session write operations and by a catch-up job. The materialization horizon should be explicit, for example generate from today through the maximum supported booking window plus a safety buffer.

## Target projection

`vw_BookableSessionSlots` replaces service-side slot projection for reads. It should include only active sessions, materialized occurrences, non-closed dates, non-deleted rows, and reservations that count against capacity.

```sql
CREATE VIEW dbo.vw_BookableSessionSlots AS
WITH ReservationAggregates AS
(
    SELECT
        r.TenantId,
        r.SessionId,
        r.[Date],
        COUNT(r.Id) AS ReservationCount
    FROM dbo.Reservations r
    WHERE r.IsHold = 0
      AND r.DeletedAt IS NULL
      AND r.Status NOT IN (2, 3, 4) -- Cancelled, Rejected, Expired
    GROUP BY r.TenantId, r.SessionId, r.[Date]
)
SELECT
    o.TenantId,
    o.SessionId,
    o.[Date],
    o.StartTimeUtc,
    o.EndTimeUtc,
    s.TotalSeats,
    COALESCE(ra.ReservationCount, 0) AS ReservationCount,
    CASE
        WHEN s.TotalSeats - COALESCE(ra.ReservationCount, 0) < 0 THEN 0
        ELSE s.TotalSeats - COALESCE(ra.ReservationCount, 0)
    END AS AvailableSeats
FROM dbo.SessionOccurrences o
JOIN dbo.Sessions s
    ON s.TenantId = o.TenantId
   AND s.Id = o.SessionId
   AND s.DeletedAt IS NULL
LEFT JOIN ReservationAggregates ra
    ON ra.TenantId = o.TenantId
   AND ra.SessionId = o.SessionId
   AND ra.[Date] = o.[Date]
LEFT JOIN dbo.SessionClosedDates cd
    ON cd.TenantId = o.TenantId
   AND cd.SessionId = o.SessionId
   AND cd.[Date] = o.[Date]
WHERE cd.[Date] IS NULL
  AND s.Status = 0; -- Active
```

Booking-window predicates should be applied in the repository query, not inside the view, because they depend on the request time and requested range. The repository should compare occurrence timestamps against the normalized range and current UTC instant.

## Dedicated read model and repository contract

Add a new keyless EF model for the view instead of reusing reservation aggregation models:

```csharp
public sealed class BookableSessionSlotProjection
{
    public string TenantId { get; set; } = string.Empty;
    public Guid SessionId { get; set; }
    public DateOnly Date { get; set; }
    public DateTimeOffset StartTimeUtc { get; set; }
    public DateTimeOffset EndTimeUtc { get; set; }
    public int TotalSeats { get; set; }
    public int ReservationCount { get; set; }
    public int AvailableSeats { get; set; }
}
```

Expose only read-specific query methods:

```csharp
internal interface IBookableSessionSlotReadRepository
{
    Task<IReadOnlyList<BookableSessionSlotProjection>> GetBySessionAsync(
        Guid sessionId,
        DateOnly dateFrom,
        DateOnly dateTo,
        DateTimeOffset now,
        CancellationToken cancellationToken);

    Task<IReadOnlyList<BookableSessionSlotProjection>> GetByDescriptorAsync(
        SessionDescriptor descriptor,
        DateOnly dateFrom,
        DateOnly dateTo,
        DateTimeOffset now,
        CancellationToken cancellationToken);
}
```

`SessionBookableDateQueryService` should then stop loading full session aggregates for slot projection. Its responsibility becomes input normalization plus delegation to `IBookableSessionSlotReadRepository`.

## Migration sequence

1. Create `SessionClosedDates` and backfill it from `SessionBookingPolicies.ClosedDates` JSON.
2. Update session policy writes to persist closed dates relationally. Keep JSON writes only as temporary compatibility if needed.
3. Create `SessionOccurrences` and backfill occurrences for the supported booking horizon.
4. Generate and maintain future occurrences when sessions are created, opened, cancelled, archived, or when recurrence fields change.
5. Add `vw_BookableSessionSlots` and its keyless EF model.
6. Add `IBookableSessionSlotReadRepository` and route `SessionBookableDateQueryService` through it.
7. Remove in-memory recurrence expansion once parity tests prove the view covers zero-reservation and closed-date cases.
8. Retire JSON closed-date reads from the slot query path.

## Correctness checks

Replacement is complete only when tests cover these cases:

- Future occurrence with zero reservations appears with `ReservationCount = 0` and `AvailableSeats = TotalSeats`.
- Closed occurrence is excluded even when reservations exist for that date.
- Cancelled, rejected, expired, hold, and soft-deleted reservations do not reduce availability.
- Over-capacity reservation counts produce `AvailableSeats = 0` instead of a negative number.
- Date-range queries return only materialized occurrences inside the requested range.
- Multi-tenant filters prevent cross-tenant slot leakage.
- Descriptor-based calendar queries do not require loading complete session entities.

## Non-goals

- Do not move reservation creation, move, cancellation, or capacity enforcement commands into the view.
- Do not remove command-side booking validation or reservation locks.
- Do not introduce a second recurrence engine in application code after occurrences are materialized.
