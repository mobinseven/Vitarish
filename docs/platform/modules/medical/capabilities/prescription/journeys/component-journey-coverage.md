# Prescription Component-to-Journey Coverage Matrix

Date created: 2026-07-08

## Scope and Source of Truth

- **App:** Clinic Owner
- **Module:** Medical
- **Capability:** Prescription
- **Related apps:** Clinic Owner, Support
- **Related modules:** Medical reference data, provider adapters, platform audit/recovery services
- **Evidence sources:** Prescription implementation matrix, platform prescription journeys, Clinic Owner prescription journeys, requested component coverage inventory.
- **Confidence level:** Medium — route/page/component identifiers follow the current implementation matrix; future implementation may split components further.

This folder is the accepted prescription capability source of truth for shared prescription journeys. Clinic Owner journey docs link here for app-specific navigation and workflow traceability.

## Command / Query Boundary

| Boundary | Rule |
| --- | --- |
| Commands | Draft creation, item changes, provider selection, eligibility record, submit, edit, cancel, fallback, template mutation/loading, credential actions, and reconciliation actions mutate prescription or operational state. |
| Queries | Lists, detail views, timeline, eligibility reads, provider/capability reads, template reads, operational dashboards, print previews, and reconciliation queues return data without mutation. |
| State owner | Prescription owns prescription lifecycle state, draft/template state, submission/recovery state, credential setup state, and reconciliation records. Medical owns persisted reference codes and search projections. |
| Consumers | Clinic Owner pages compose these components; provider adapters and Medical reference queries remain behind application/client boundaries. |
