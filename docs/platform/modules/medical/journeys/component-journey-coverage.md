# Medical Interface Component-to-Journey Coverage Matrix

Date created: 2026-07-08

## Scope and Source of Truth

- **App:** Platform
- **Module:** Medical
- **Capability:** Reference data administration, code-system registry, import operations, local curation, service valuation, reference search
- **Related apps:** Clinic Owner
- **Related modules:** Prescription consumes Medical reference data but does not own persisted code-system, import, curation, valuation, or reference-search state.
- **Evidence sources:** Existing Medical owner journeys, Prescription implementation matrix, requested component coverage inventory.
- **Confidence level:** Medium — component names are mapped from current journey intent and documented routes; final route/component implementation may refine identifiers.

This matrix is the explicit coverage source for standalone Medical Interface components that support reference/admin journeys. Prescription-specific surfaces are covered in the accepted prescription capability source of truth: [`../capabilities/prescription/journeys/component-journey-coverage.md`](../capabilities/prescription/journeys/component-journey-coverage.md).

## Command / Query Boundary

| Boundary | Rule |
| --- | --- |
| Commands | Create, edit, activate, import, curate, map, rebuild, and publish actions mutate Medical-owned state and must surface validation and dependency failures explicitly. |
| Queries | List, detail, search, preview, diagnostics, valuation lookup, and dashboard read models return data without mutating Medical state. |
| State owner | Medical owns code systems, releases, import batches, local curated references, code maps, service valuations, and search projections. |
| Consumers | Prescription and other modules query Medical references through read contracts and do not persist provider code ownership locally. |
